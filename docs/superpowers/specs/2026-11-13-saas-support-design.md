# 软件与 SaaS 技术支持知识助手设计

状态：用户已选择软件 / SaaS 方向并授权按前述规划继续；本文件记录首期实现与后续范围。

## 定位与目标
面向技术支持、实施人员和产品使用者，依据产品资料提供可追问、可溯源的产品使用与部署排障答案。首期示范产品为本仓库 RAG Knowledge Base；语料注明代码快照来源，不冒充真实厂商工单或未经验证的正式产品版本。

## 方案取舍
1. 只更换页面名称和角色提示词：交付快，但不能改善追问检索和澄清行为。
2. 在既有顺序管线上增加技术支持配置、历史改写和结构化回答：本期采用；沿用 FAISS、权限过滤、引用和会话存储。
3. 全面上线 Agent、工单系统与企业组织权限：范围过大，待业务评测和真实使用反馈后分期实施。

## 首期契约
- 网页 /qa/ask 默认 support_answer_v1；只允许该模板与 rag_context_cited。实验脚本仍可使用内部模板，原 RetrievalConfig 默认与历史评测保持不变。
- 历史只用于承接语境，不作为本轮事实证据；检索仍须传 viewer_user_id 和 document_id。
- 仅支持模式且存在历史时最多一次查询改写，8 秒超时；非法 JSON、空文本、错误码/版本/配置键丢失时回退原问题，不记录原始历史到日志。
- 支持答案使用受校验 JSON：status、answer、clarifying_questions。status 包含 answered、partial、needs_clarification、insufficient_evidence、conflicting_evidence。
- 澄清最多 2 个问题；澄清不是拒答，必须保存在会话并参与下一次上下文。资料不足才设置 refused。未知状态/坏 JSON 安全降级为资料不足，不展示原始 JSON。
- 事实性回答至少有一条来自实际提供给模型的上下文的有效引用。无引用的事实答案降级为资料不足；有效编号不等于语义支持，语义仍需人工/模型评测。
- 上下文截断后引用必须只映射实际提供的片段，不能引用因预算未进入上下文的文档。
- 新消息字段可选，历史 JSONB 消息不需要数据库迁移；老消息按旧拒答标记展示。
- 返回增加 retrieval_query、query_rewritten、rewrite_failed、output_validation_failed；token 汇总包括改写和回答，不宣称已有真实线上性能数据。
- 语料独立放 data/support_corpus，默认不随构建导入；沿用 build_index.py --corpus 显式入库。导入会成为公共示范资料，禁止放私有文档。
- 本期评测集为少量可审阅草稿；不上传或改动在线 Langfuse 数据集。记录模板版本与场景，保留原通用基线。

## 本期交付
