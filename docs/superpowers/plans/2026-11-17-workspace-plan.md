# 界面工作区实施计划

1. 添加经过用户权限校验的文档可读内容接口，并验证本人、公共、跨用户与空内容情况。
2. 建立全局主题、右侧单文档预览及可恢复收放状态，保留挂载中的会话。
3. 改造左栏分组收放、设置、聊天示例和引用文件名入口。
4. 统一登录、注册、验证、找回与注销页面的外观和表单样式。
5. 验证后端测试、类型、lint、生产构建以及桌面和窄屏交互，记录结果。

重点回归：快速切换文档不串内容；收起聊天后请求继续；展开引用不直接展示原文；浅色与深色的文字对比；主题在登录跳转与刷新后保留。

## 实施与验证结果

以上五步已完成。文档预览接口沿用文档可见性权限校验，展示当前分块策略下已保存的解析文本及页码；空内容、加载失败和重试都有独立状态。前后端需一起部署，无新增数据库迁移。

补充交互：发送问题后，在消息区显示带状态播报的“正在思考…”与轻量旋转标识；成功或失败后自动移除。收起对话不打断请求，系统减少动态效果设置下停止动画。

- 后端完整测试：605 passed，包含新增文档预览接口的 10 项测试。
- 前端：ESLint、TypeScript 检查及 Next.js 生产构建通过。
- Chrome 浏览器回归：默认深色、示例文字及纵向排列、分组收放、对话状态保留、单文档替换、快速切换请求竞争、失败重试、历史会话续聊、多处引用高亮、主题持久化、设置中的退出及注销入口通过。
- 思考标识回归：等待时出现，成功及失败后消失，失败后问题恢复到输入框；收起再展开对话不影响完成请求。
- 桌面与手机截图已人工检查，覆盖浅色设置、右侧预览、窄屏返回对话以及账号页面。

浏览器回归使用模拟 API 数据，未调用真实模型、邮件服务或生产数据库；真实文档解析效果需在部署后用上传资料核对。预览展示解析文本，不还原 PDF 等文件的原始版式。部署后仍需核对真实资料。
